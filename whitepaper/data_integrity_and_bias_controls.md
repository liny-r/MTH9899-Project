# Data Integrity and Bias Controls

The pipeline employs several safeguards to ensure features and targets are free of look-ahead, survivorship, and calendar-related biases.

**Trading calendar.** Rather than relying on calendar arithmetic, the pipeline derives its trading day calendar implicitly from the set of intraday data files present on disk. All backward-looking lags — including the "previous trading day" lookup and multi-day momentum windows (5-day, 21-day) — are computed via index positions within this file-derived trading day list. This ensures that weekends and market holidays are never inadvertently treated as valid observation dates.

**Survivorship bias.** The cross-sectional universe is determined independently each day by the securities present in that day's data files. Cross-sectional normalization steps (MAD winsorization, z-scoring) are computed within each date's available universe, so the pipeline never implicitly assumes a security survived to any future date. Securities that delist or drop out of coverage simply cease to appear in subsequent training rows. The one nuance is a warm-up effect: securities with fewer than 60 trading days of history are excluded from time-series normalization due to the rolling window's `min_periods` requirement, slightly reducing cross-sectional breadth in early 2010. This is a data completeness constraint rather than survivorship bias.

**Look-ahead bias.** All time-series z-scores use a one-period shift before applying the rolling window, ensuring the standardization at date *t* depends only on observations prior to *t*. The `StandardScaler` used for model inputs is fit exclusively on the 2010–2013 training set and applied without refitting to the 2014 validation and holdout test sets. Walk-forward cross-validation uses strictly expanding training windows; critically, hyperparameters reported for the 2014 validation fold were selected using the 2013 validation fold, so the reported out-of-sample R² on 2014 is uncontaminated by any tuning on that period.
